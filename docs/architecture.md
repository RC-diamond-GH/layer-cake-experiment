# 组件与扩展实验

## 1 模块职责

| 模块 | 职责 |
| --- | --- |
| `context` | 系统提示、全局材料、消息、可见工具及版本化上下文 |
| `model` | 异步模型 trait、条件脚本模型与 OpenAI-compatible 适配器 |
| `tool` | 工具 trait、定义到执行对象的注册表、内存读写工具 |
| `record` | 运行对象索引、因果观测、公共调用记录、快照和文件存储 |
| `react` | 有界生成、顺序执行工具、写回及明确终态 |
| `experiment` | Rust 装配入口、配置、边界控制、原实验回放编排 |
| `events` | 保留事件、订阅匹配、投递去重、取消与接收队列 |
| `environment` | 模拟时钟、版本化熔炉和计时器环境 |
| `reactive` | 轮询策略、事件唤醒策略与确定性实验装配 |
| `replay` | 模型与工具替身、共享调用游标及首个请求分歧 |
| `report` | 静态 HTML、运行比较及调用差异 |
| `cli` | 交互控制、保存记录查询、报告及回放命令 |

每个模块通过 `mod.rs` 组织公开接口，具体实现位于子文件。第一种 Agent 保持具体的 `ReAct` 类型；实验控制器组合基础组件并声明边界。

## 2 上下文、调用与身份

Agent 持有上下文写入权。每次消息更新增加版本；公共模型调用入口保存实际输入快照，后续修改保留旧版本。运行、Agent、上下文、模型、工具、资源及订阅使用对象身份。观测共享运行 ID、对象 ID、记录 ID、全局顺序、时间和可选来源记录。

模型调用输入包含上下文与生成参数。输出保存回答、工具调用、停止原因和提供方返回的用量；工具记录保存参数、结果及错误。工具调用的来源指向模型记录，从而定位该动作实际依据的上下文版本。自定义观测使用同一入口，内容由实验定义。

ReAct 将模型回答和工具调用写回后，按输出顺序执行可见工具。正常完成、模型错误、工具错误、截断、内容过滤、未知停止原因和轮次耗尽分别保存状态。终态吸收后续步进；响应式控制器仅在正常回答结束后，经明确的重新打开操作继续任务，原轮次预算保持累计。

## 3 熔炉与响应式执行

熔炉保存原料、燃料、产物、作业和版本。启动作业消费资源并确定完成时刻；模拟时钟到达完成时刻后产生结果与完成事件。工具负责主动启动、查询、取出；订阅负责绑定来源、作业及接收者。轮询版本主动查询进度，响应式版本等待匹配事件唤醒。

### 3.1 订阅规则

事件身份在事件源内稳定生成，事件携带来源和作业身份。发布入口保留首次事件；重复身份通过去重规则处理。订阅按来源与作业匹配，登记时检查已保留事件，因此完成早于订阅也能投递。每个订阅使用 `DeliveryGate` 保存活动标志与已准入事件集合，同一事件对同一订阅最多准入一次。取消关闭闸门并清理该订阅尚未消费的队列项。队列按确定性顺序交付。

### 3.2 等待与资源刷新

`ScenarioConfig` 提供 `duration`、`completion_before_subscribe`、`duplicate_notification`、`mutate_while_waiting`。三项边界场景分别检查先完成后登记、重复通知和等待期间资源变化。驱动器唤醒时读取当前资源状态与版本，事件作为触发依据，资源快照作为当前行动依据。

计时器使用相同事件与订阅接口替换熔炉来源。事件发布、匹配、入队、出队、控制决定、上下文刷新及模型调用均记录关联身份，可沿模型调用来源回溯唤醒原因。

## 4 扩展复用与接口调整

| 类别 | 组件或变化 | 原因 |
| --- | --- | --- |
| 直接复用 | `ModelClient`、`Tool`、上下文、工具注册表、调用入口、对象索引、文件记录、报告 | 调用和观测格式独立于控制机制 |
| 新增 | 模拟时钟、版本化资源、事件、订阅、队列、响应式驱动器 | 表达耗时作业与外部变化驱动 |
| ReAct 扩展 | 正常终态受控重开，保留累计轮次 | 一个外部任务包含等待前后多次生成阶段 |
| 记录扩展点 | 自定义对象种类与自定义观测内容 | 资源和订阅沿用统一身份与来源字段 |
| 工具执行扩展点 | 注册表执行覆盖入口 | 回放逐次核对请求并替代副作用 |
| 模拟结果投影 | 从工具返回保存的环境状态恢复确定性状态 | 回放时保持后续时钟与事件行为一致 |

控制方式的差异集中在实验控制器和响应式模块。基础调用入口继续保存原始请求，报告消费公共记录格式。该组织保留了具体机制的可审阅代码，同时让事件源替换和实验比较共享观察设施。

## 5 存储与回放边界

一次运行保存配置、对象索引、观测、不可变快照及结果摘要。运行 JSON 是报告、查询、比较与回放的共同输入；保存通过临时文件和原子替换完成。摘要中的边界数和报告中的记录顺序给出截断位置。

回放重建原控制器，以保存结果替代外部调用。共享游标同时约束模型与工具调用顺序；上下文内容、版本、参数及可见工具均参与请求核对。已确认控制输入按原边界重放。模拟状态从记录结果投影，时钟与订阅由确定性实现重新执行。回放成功表明记录中的调用请求序列在该实现与配置下可重现。
